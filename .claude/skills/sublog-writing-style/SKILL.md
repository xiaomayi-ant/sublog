# sublog 写作规范

这套规范是从实际改稿里提炼出来的，不是凭空定的——每一条后面标了它是从哪次修改里确认下来的，方便判断边界情况该怎么办。以 `src/content/notes/computer-use-bet.md` 的最终版本和 `src/content/llm/jev-decision-paradigm.md` 为参照实例。

## 写之前：先核实，不要凭训练知识写

四个分类里的内容大多涉及近期发布的模型、产品、事件——很可能晚于训练数据截止时间，或者细节在记忆里本来就模糊。**开始组织论点之前，先用 WebSearch/WebFetch 核实关键事实**：官方定义、具体数字、时间线。找不到一手来源（官方博客、模型卡片、系统卡）时用高质量二手来源转述，并在脚注里如实标注"经 XX 转述"，不要把转述包装成一手引用。

对存在方法论争议的数字（比如厂商自评），同时找至少一份独立/批评性来源，两边都呈现，不要只引对自己论点有利的一半。

## 分类归属

- `harness`：执行框架、工具边界、agent 编排
- `llm`：模型行为、模型架构、模型本身的能力/局限
- `eval`：评估设计、评测方法论、效力评估
- `notes`：还没长成文章的观察，门槛最低

一篇稿子如果同时沾两个分类（比如"评估一个新模型"），看**核心论点**落在哪——论点是"这个模型代表什么范式"就进 `llm`，论点是"这套评测方法本身有没有问题"就进 `eval`。

## 标题

- **只写事实，不写评论/看法**。反例（改之前）："Computer Use 的赌注：押的不是智能，是「越权率」"——"赌注"是评论性框定。正例（改之后）："Computer Use 与越权率"。
- **一行放完**，核心信息压在 9 个汉字左右（不含英文专名和标点）。写完在浏览器里实际看一眼是否换行，换行就再压缩。
- 英文专名（模型名、产品名）保留原文，不翻译、不加书名号。

## 主次结构

写之前先想清楚：这篇的**主题**是什么，哪些是**支撑证据**。常见错误是拿一个具体的评测数字/案例当主题，把真正的论点（"这条产品线在解决什么问题""这个范式和过去的区别是什么"）压成背景板。

判断方法：`description` 第一句必须是主题，第二句才轮到证据。写完自查——如果把第二句删掉，第一句还成不成立、够不够吸引人；如果第一句本身就是一个孤立数字或案例，说明主次颠倒了，需要重写。

## 标题语言（h2/h3）

- 内容特定、承载具体论点的小标题用中文，比如"一个越权的场景""变了的不是速度，是训练目标"。
- 报告体的通用结构标签可以用英文，目前确认过的两个：`Evaluation`（证据与数字部分）、`Observations`（收尾的分点判断）。不要随意发明新的英文标签——只有这两个是已经在多篇文章里重复使用、确认下来的。

## 引用格式

- **每个来源第一次出现就要挂脚注**，不能先裸讲一个来源名字（"系统卡里说……"），过几段才补引用。来源名字本身要能让读者知道这是谁发布的，不能是"某评测"这种无主语的说法。
- 官方一手材料（博客、模型卡、系统卡）优先直接逐字引用（blockquote + 脚注），不要转述改写官方原话——转述容易引入自己都没意识到的偏移。
- 脚注格式：`[^n]: 作者/机构. "标题." *发布物名称*, 日期。URL ——补充说明（如果这条脚注还承载了方法论细节或额外背景）。`
- 同一个来源在文中多处引用，复用同一个脚注编号，不要重复建号。
- 日期用绝对日期（"2026年9月"、具体到日更好），不用"最近""上个月"这类相对说法。

## 内部链接

**站内其它文章的交叉引用放到结尾脚注，用纯文本（仓库内路径），不要做成行内超链接。** 这是从 `computer-use-bet.md` 最后一轮改动里明确下来的——行内链接会打断读者对当前论点的注意力，交叉引用属于"读完这篇还想深入"的可选项，放脚注更合适。格式参照现有例子：

```
[^6]: 延伸阅读——一句话说清两篇文章的关系：《标题》，sumoer.fun/blog/分类/slug
```

（`oui-1-generative-ui-diffusion.md` 里还留着旧的行内超链接写法，是规范定下来之前写的，不代表当前标准——改到这篇时应该一并挪到脚注。）

## 标点

- 中文句子里一律全角标点：，。；：（）——半角逗号/冒号/括号混进中文句子里是常见疏漏，写完用下面的命令扫一遍：
  ```
  grep -nP '[\x{4e00}-\x{9fff}],|,[\x{4e00}-\x{9fff}]|[\x{4e00}-\x{9fff}]\(|\)[\x{4e00}-\x{9fff}]' 文件路径
  ```
- 中文短语用「」，不用直引号 `""`。直引号只留给逐字的英文标题/术语/原文引用（比如 blockquote 里的英文原文，或者行文中夹的英文专有说法）。写完用下面的命令扫一遍有没有直引号包住了中文：
  ```
  grep -nP '"[\x{4e00}-\x{9fff}]|[\x{4e00}-\x{9fff}]"' 文件路径
  ```

## 段落结构

具体场景/案例先出现，抽象结论后出现——不要开篇就甩一个论断再补案例。参照 `computer-use-bet.md` 的"一个越权的场景"一节：先讲两个模型面对同一个任务分别会怎么做，再落到"区别不是「谁更聪明」，是有没有能力在做不到的时候停下来"这句结论。
